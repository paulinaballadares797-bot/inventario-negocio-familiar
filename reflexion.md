# Reflexión final

## Aprendizajes
Durante este proyecto aprendí a usar Git y GitHub como herramientas de 
control de versiones, incluyendo la creación de ramas, commits 
descriptivos, la gestión de Pull Requests y la coordinación de un 
aporte externo (colaboración con un compañero del aula).

## Dificultades encontradas
Lo que más se me dificultó fue entender y resolver el conflicto entre 
ramas: al modificar la misma línea de un archivo desde dos ramas 
distintas, GitHub no pudo fusionar los cambios automáticamente, y tuve 
que aprender a identificar las marcas del conflicto (`<<<<<<<`, 
`=======`, `>>>>>>>`) y decidir manualmente qué versión conservar.

## Cómo se resolvió
Revisé con calma el editor de conflictos de GitHub, comparé ambas 
versiones de la línea en disputa y elegí la más adecuada, eliminando 
las marcas del conflicto. Luego confirmé la resolución y completé el 
merge del Pull Request hacia la rama principal.

## Importancia del proyecto
Este proyecto demuestra que herramientas como Git y GitHub, comúnmente 
usadas para desarrollo de software, también son útiles para gestionar 
y documentar proyectos de forma organizada y colaborativa, incluso sin 
escribir código. Además, resolver un conflicto real me ayudó a entender 
por qué el trabajo en equipo con control de versiones requiere buena 
comunicación entre colaboradores.
